网页压缩系统使用文档

本页模拟一个完整的系统说明中心，覆盖资源扫描、打包压缩、恢复校验、图表展示与离线约束。

内容采用统一的标题、说明、代码块和提示框结构，并通过步骤卡片与警告卡片提供重复文本样本，以便测试文本压缩与页面恢复逻辑。

资源扫描

资源扫描阶段负责收集 HTML、CSS、JS 与图片文件，并建立相对路径索引。为了让后续压缩处理稳定，扫描阶段通常会保留页面入口顺序、资源引用顺序和文件清单顺序，避免恢复结果和原始结果出现不必要差异。

function scanSite(root) {
  const htmlFiles = listFiles(root, ".html");
  const cssFiles = listFiles(root, ".css");
  const jsFiles = listFiles(root, ".js");
  return { htmlFiles, cssFiles, jsFiles };
}
说明：资源扫描不应依赖网络，不应尝试下载外部资源，也不应隐式改写相对路径。

文本压缩

文本压缩更容易从重复结构中受益，例如重复导航、重复页脚、重复卡片和重复表单。一个设计良好的测试样本不需要完全重复，也不应该完全随机，而是应该接近真实网页并保留足够多的共同字段。

const repeatedBlock = "<article class='article-card'>...</article>";
const repeatedMeta = "article-title article-meta article-summary article-tag";
return repeatedBlock + repeatedMeta;
说明：相似但不完全相同的段落能够同时测试模板复用和局部差异处理。

图片压缩

图片样本应覆盖横幅、头像、画廊图和背景纹理，但总大小仍要控制在限制范围内。采用 Pillow 本地生成抽象渐变图和几何图，可以得到稳定的测试资源，同时避免外部版权和联网下载问题。

image = gradient_image((1280, 720), (40, 92, 160), (228, 126, 98))
draw.ellipse((120, 80, 520, 480), fill=(255, 255, 255, 120))
draw.rectangle((680, 140, 1140, 520), fill=(18, 38, 88, 110))
说明：同尺寸、不同色调的图片有助于观察压缩率变化，而不会引入额外网络依赖。

路径恢复

恢复阶段不只是把文件写回磁盘，更重要的是验证相对路径是否保持一致。任何一个页面中如果存在脚本路径、样式路径或图片路径错误，都会导致本地打开失败，因此路径检查必须覆盖新增页面和原有页面。

<link rel="stylesheet" href="css/forms.css">
<script src="js/search.js"></script>
<img src="images/gallery4.jpg" alt="gallery">
说明：路径统一使用相对路径，恢复后不依赖服务器路由即可打开。

样式拆分

通过增加 animation.css 和 forms.css，可以提升文本文件数量，同时把动画、表单和长页面组件独立出来。这样既能维持真实站点结构，也能让压缩算法接触到更多重复的 CSS 属性和值。

.form-input {
  display: block;
  padding: 12px 14px;
  border: 1px solid #cad4e3;
  border-radius: 14px;
}
说明：样式拆分不等于引入第三方框架，仍然可以保持纯本地静态站点。

搜索模块

搜索模块用于增强 FAQ 与博客页面的交互性。实现时反复使用 querySelector、querySelectorAll、classList、dataset 和 textContent，既能构成真实的源码文本，也能在本地页面中提供简单的关键字筛选和匹配高亮。

const input = document.querySelector("[data-search-input]");
const cards = document.querySelectorAll("[data-search-card]");
cards.forEach(function (card) {
  card.classList.remove("is-hidden");
});
说明：搜索逻辑不依赖模块系统，不使用 import/export，便于直接在本地 HTML 中引用。

图表模块

图表模块通过 DOM 节点创建条形图和图例，用于模拟压缩率、传输率等结果展示。页面不引入任何第三方图表库，但仍可通过统一的条结构、标签结构和说明结构体现真实网页中的数据展示场景。

const bar = document.createElement("div");
bar.classList.add("chart-bar-fill");
bar.style.width = percent + "%";
bar.textContent = label;
说明：图表只需表达关系，不需要复杂渲染，因此原生 DOM 已足够满足样本需求。

数据校验

数据校验应覆盖文件数量、图片数量、路径正确性和页面可打开性。特别是当样本站点不断扩展时，文件数量是否达到目标、图片是否足够、路径是否仍为本地相对引用，都需要在最终检查中明确输出。

return {
  textFileCount: countFiles(root, [".html", ".css", ".js"]),
  imageCount: countFiles(imagesRoot, [".jpg", ".jpeg", ".png"])
};
说明：最终结果应能直接说明是否已满足进阶样本站点要求。

离线打开

所有页面都应能通过文件系统直接打开，而不是依赖开发服务器。为此需要避免绝对 URL、避免远程脚本、避免 CDN 和远程字体，并确保所有样式、脚本和图片路径都指向同级目录下的本地资源。

<a href="pricing.html">套餐</a>
<link rel="stylesheet" href="css/animation.css">
<script src="js/charts.js"></script>
说明：离线打开检查至少要验证十个页面的导航互跳和新增图片的可见性。

样本扩展

当需要继续扩展样本时，应优先增加真实结构，例如博客、FAQ、价格表、文档页和画廊页，而不是随意堆砌无意义字符串。真实结构能产生更多可重复的标签模式、样式模式和脚本模式，对网页压缩系统更有测试价值。

const pages = [
  "index.html", "about.html", "services.html", "products.html", "gallery.html",
  "blog.html", "docs.html", "pricing.html", "faq.html", "contact.html"
];
return pages.length;
说明：样本扩展的目标不是炫技，而是让压缩、恢复与校验更贴近真实输入。

步骤一

整理资源目录，确认所有页面、样式、脚本和图片都位于站点内部，并保持相对路径结构清晰。

步骤二

扩展文本文件数量，优先增加真实页面、样式拆分和可复用脚本，而不是无意义占位文件。

步骤三

扩展图片数量，采用本地生成策略控制尺寸、色调和体积，避免引入网络资源。

步骤四

统一导航和页脚，避免新页面出现孤岛链接，确保每个页面都能从顶部和底部访问。

步骤五

补充搜索和图表等轻量交互，使站点更接近真实网页系统，同时保持脚本纯原生可本地运行。

步骤六

在最终检查中统计文件数量、图片数量和引用路径，并运行图片脚本，确认新增资源完整落盘。

警告一

不要把外部 CDN 链接混入样本站点，否则无法满足离线打开要求。

警告二

不要修改压缩算法工程代码，样本扩展应局限在示例站点和资源生成脚本中。

警告三

不要把新增文件压成一行，保留正常缩进和换行对文本压缩测试更有代表性。

警告四

不要引入第三方框架，样本站点需要保持纯本地 HTML、CSS 和 JS 结构。

警告五

不要遗漏页脚和导航中的新链接，否则本地跳转检查会出现断链。

警告六

不要只统计页面数量，图片数量和总大小同样属于进阶要求的一部分。
