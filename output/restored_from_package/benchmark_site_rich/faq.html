常见问题与检索中心

围绕网页压缩、资源恢复、图片压缩、传输优化和数据结构整理出二十四条问答，保持统一问答结构并附加搜索能力。

每条回答都采用两到三句话，内容自然、结构重复、字段统一，适合作为文本压缩与恢复测试中的问答型样本。

网页压缩样本为什么要保留大量重复结构？

因为真实网页天然包含重复导航、重复页脚、重复卡片和重复按钮。保留这些结构可以让压缩算法面对更真实的输入，而不是被随机文本误导。

网页压缩

恢复后的页面最容易在哪些地方出错？

最常见的是相对路径错误，例如图片路径、样式路径和脚本路径写错层级。其次是导航链接漏改，导致新页面无法从其他页面跳转过去。

资源恢复

为什么图片要本地生成而不是下载素材？

本地生成可以保证资源稳定、可重复、无网络依赖。对课程实验和离线打开来说，这比下载外部素材更可控，也更容易统一体积。

图片压缩

如何在增加页面和图片的同时控制总大小？

关键是使用适中的图片尺寸和可压缩的抽象图案，并避免无意义的大体积资源。文本页面数量增加并不会显著推动体积上升，通常瓶颈仍在图片资源。

传输优化

FAQ 为什么适合作为压缩测试内容？

FAQ 具有高度重复的标题、答案和标签结构，同时每条内容又存在轻微差异。这样既保留真实网页形态，也能为文本压缩提供稳定的重复模式。

数据结构

页面搜索需要多复杂才有价值？

不需要复杂。只要能够完成关键字归一化、卡片过滤和匹配高亮，就足以形成真实的前端脚本结构，并帮助检查本地页面交互是否正常。

搜索模块

不引入第三方图表库会不会太简陋？

不会。对于样本站点来说，只要能表达压缩率和传输率的相对关系，原生 DOM 条形图已经足够。这样还能避免外部依赖，提高离线可用性。

图表展示

为什么必须避免 CDN 与外部链接？

因为题目要求所有页面都能本地打开。只要存在 CDN 或远程脚本，离线环境下页面就可能失效，压缩和恢复测试也会掺入不相关变量。

离线约束

新增页面应该优先补什么内容？

优先补真实网页常见的结构，例如博客、文档、价格页和问答页。这样不仅能增加文件数量，也能增加可重复的标题、段落、表单和列表结构。

页面扩展

为什么新增两个 CSS 文件而不是把内容塞进原文件？

因为文件拆分本身就是样本站点规模的一部分，同时还能保留更多重复的样式属性。对于压缩算法来说，多文件场景往往比单文件更接近真实输入。

样式拆分

为什么新脚本要求挂到 window 上？

这是为了让脚本能直接在本地 HTML 中引用，不依赖模块打包工具。挂到 window 上也更符合纯静态站点的简单使用方式。

脚本组织

FAQ 页还需要表单样式吗？

需要，因为搜索面板和订阅面板都会复用表单结构。统一的输入框、标签和按钮样式能增加样式重复度，并提升页面的一致性。

表单样式

页脚为什么也要加入所有新链接？

因为真实网站往往在页脚保留完整导航。这样不仅方便本地检查跳转完整性，也会带来重复链接文本和重复 DOM 结构。

页脚导航

顶部导航必须所有页面都一致吗？

最好一致。统一导航能降低断链风险，也让样本站点更像一个完整产品，而不是临时拼接的页面集合。

顶部导航

为什么博客页还要加分类和归档？

分类和归档是博客类站点很常见的重复区块。它们能稳定增加短文本重复、链接重复和列表结构重复。

博客结构

文档页里的伪代码有什么作用？

伪代码可以增加另一类文本模式，让样本站点不仅有自然语言，也有接近源码的内容。这样更适合观察压缩算法面对混合文本时的表现。

文档内容

价格页为什么值得加入基准站点？

价格页天然包含价格字段、特性列表、对比表和问答说明。它既是常见网页形态，也会产生大量重复字段和重复容器。

价格结构

新增图片为什么选择画廊图和背景图？

因为这两类图片最常出现在静态站点里，而且容易通过抽象图案生成。它们既能提升页面观感，也能补齐图片数量要求。

图片资源

为什么特别强调 UTF-8 编码？

因为新增中文页面如果编码不一致，容易在本地打开时出现乱码。统一 UTF-8 可以保证 HTML、CSS 和 JS 文本稳定可读。

编码规范

重复 class 名真的有测试价值吗？

有。重复 class 名能反映真实网页组件的复用程度，同时也会直接影响文本压缩算法对源码模式的识别效率。

重复结构

最终检查为什么要输出文件数量？

因为文件数量是题目要求的一部分，不能只凭感觉判断。明确输出文本文件数量和图片数量，才能证明样本规模已经满足目标。

最终检查

如何确认总大小仍在限制内？

最直接的方法是统计目录总大小。通常这类静态样本站点的主要体积来自图片，只要控制图片尺寸和压缩质量，五十兆上限并不难满足。

体积控制

资源生成脚本需要保留旧逻辑吗？

需要。新增逻辑应该在原脚本基础上追加，不能破坏已有的 basic 和 rich 图片生成流程，否则会影响旧样本目录的完整性。

脚本兼容

确认页面可本地打开时重点看什么？

重点看页面能否渲染样式、脚本是否报错、图片是否显示以及导航链接是否跳转成功。这些检查组合起来，才能说明恢复后的站点真正可用。

本地校验
